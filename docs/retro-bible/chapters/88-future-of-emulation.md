# Future of Emulation

Emulation is not finished. That is part of what makes it worth writing about carefully.

This chapter is the skeleton for future-facing topics: project sustainability, accuracy, current platforms, hardware changes and the preservation work still ahead.

## Historical Context

Every generation once seemed too complex to emulate. Then documentation improved, hardware got faster, developers did the work and the impossible became ordinary.

## Practical Advice

- Prefer maintained projects.
- Record versions because compatibility changes.
- Support upstream documentation and issue reporting.
- Keep preservation sources separate from emulator-specific working copies.
- Avoid chasing novelty when a stable setup matters.

## Preservation Notes

The future of emulation depends on documentation, hardware access, legal breathing room, developer time and community memory.

> **DAP Tip**
>
> The emulator that works today may not be the emulator you use in ten years. A clean library gives you choices.

## Common Mistakes

- Treating compatibility as permanent.
- Assuming abandoned projects are safe long-term.
- Ignoring build reproducibility.
- Forgetting that emulator developers are volunteers or small teams.

## Troubleshooting

### A project disappears

Check source mirrors, forks, release archives, documentation copies and whether the licence permits continuation.

## DAP Warning

Do not build the book around hype. Future chapters need facts, dates and version context.

# Preservation Projects and Community Efforts

Games are preserved by people before they are preserved by tools.

This chapter is the skeleton for the communities, databases, dumpers, emulator developers, archivists and documentarians who keep history playable.

## Historical Context

Many preservation efforts began as hobby projects. Over time, some became essential infrastructure: databases, DATs, emulators, scanners, dump methods and compatibility lists.

## Key Project Types

| Type | Examples |
| --- | --- |
| Verification databases | Redump, No-Intro, TOSEC |
| Emulation projects | MAME, Dolphin, PCSX2, RPCS3 |
| Metadata projects | ScreenScraper, SteamGridDB |
| Documentation | Wikis, manuals, compatibility databases |
| Community restoration | Online service revivals, translation projects |

## Practical Advice

- Credit projects clearly.
- Use official documentation where possible.
- Avoid turning community work into anonymous "the internet says".
- Preserve version numbers and dates.
- Respect project rules and licences.

## Preservation Notes

Community knowledge can be fragile. Forum posts, Discord messages and personal sites vanish. Later passes should identify durable citations.

> **DAP Tip**
>
> When a tool saves you hours, write down its name, version and source. That is respect and maintenance at the same time.

## Common Mistakes

- Using community data without attribution.
- Treating compatibility lists as permanent.
- Ignoring project scope.
- Confusing metadata projects with verification projects.

## Troubleshooting

### Project documentation conflicts

Check dates, versions, issue trackers and whether one source applies to a different platform or release.

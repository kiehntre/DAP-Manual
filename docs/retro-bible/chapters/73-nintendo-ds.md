# Nintendo DS

The Nintendo DS is where emulation stops being only about pixels and starts being about posture.

This chapter is the skeleton for preserving DS games with two screens, touch input, microphone features and emulator layout choices.

## History

The DS followed an unusual idea: two screens, one touch-enabled, in a clamshell handheld. It became a home for experiments that would not have made sense anywhere else.

## Hardware Overview

- Dual screens.
- Touchscreen.
- Microphone.
- Cartridge media.
- Wireless local play.

## Why It Mattered

It expanded what handheld games could look and feel like, especially for puzzle, adventure, training and experimental games.

## Preservation Status

Strong. Input and display layout are the practical challenges.

## Recommended Emulator

melonDS is a strong recommendation. DeSmuME remains historically important.

## BIOS Requirements

BIOS and firmware files may improve accuracy and are required for some behaviours. Verify and document them.

## Recommended File Formats

- `.nds` ROM images.
- Keep DSiWare and DSi-enhanced material separate for later coverage.

## Folder Layout

```text
/mnt/games/roms/nds/
/mnt/games/bios/nds/
/mnt/games/saves/nds/
```

## Enhancements

Screen layout presets matter more than shaders. Touch-heavy games may not be sofa-friendly.

## Common Problems

- Touch input awkward on TV.
- Screens arranged poorly.
- Missing firmware for certain features.
- Microphone input forgotten.

> **DAP Tip**
>
> Tag DS games by play style. Some are perfect on a controller; others really want a touchscreen.

## DAP Gold Standard Setup

- melonDS tested.
- BIOS and firmware recorded where used.
- Layout presets for desktop, handheld and TV.
- Saves backed up.

## What Comes Next

Next comes Nintendo 3DS, where screens, shaders and system software become more demanding.
